# 语义搜索召回优化方案

## 1. 背景

当前“相册 -> 顶部语义搜索”已经具备如下主链路：

1. 解析查询：
   - 短查询优先走本地短语义直搜
   - 复杂查询优先走 DeepSeek 结构化解析
2. 元数据过滤：
   - 时间
   - 地点
3. 粗标签过滤：
   - 命中粗标签后进入候选集
4. 向量打分：
   - 正向语义
   - 负向语义
5. 找不到时放宽时间/地点

但目前实际效果暴露出一个更关键的问题：

**不是纯粹的“排序不好”，而是“召回明显不足”。**

也就是说，很多用户认为应该能搜出来的图片，根本没有进入最终候选集。

---

## 2. 当前问题总结

### 2.1 搜索“笑脸”为空，但明显有微笑照片

这类问题通常有 4 个可能根因：

1. `DeepSeek / 本地解析出的正向语义过窄`
   - 例如只生成了接近 `a smiling face portrait` 的语义
   - 但用户照片是“人在花中微笑”“多人轻松合影”“旅游时露出笑容”
   - 这些图片虽然“快乐/微笑”，却不一定接近“正脸笑脸特写”

2. `粗标签先筛掉了图片`
   - 例如照片被打成“花草植物 / 旅游地标 / 城市街景”
   - 但解析出的粗标签偏向“人物”
   - 结果图片在进入语义打分前就已经被拦截

3. `正向语义参与阈值过硬`
   - 现在正向语义参与阈值是 `0.20`
   - 对“笑脸”“快乐的时光”这类抽象概念来说，这个阈值可能太高
   - 尤其当图片不是人脸特写，而是“场景性快乐”时，会被误杀

4. `抽象词没有做语义扩展`
   - “笑脸”当前更接近“显式笑容”
   - 但用户真正想找的往往是：
     - 开心合影
     - 旅游中的笑容
     - 聚餐中的笑容
     - 春日轻松氛围中的笑容

### 2.2 抽象语义理解能力不足

例子：

- 搜索“春天的气息”
  - 能搜出花
  - 但搜不出“人在花里拍照”“春天公园里的合影”“草地春游”

- 搜索“快乐的时光”
  - 能搜出笑脸
  - 但搜不出旅游、聚餐、生日、节庆等同样高概率承载快乐情绪的照片

根因：

当前解析层更擅长把查询变成“具体物体 / 具体场景”，
但对“抽象情绪 / 抽象氛围 / 抽象季节感”的**语义展开不够宽**。

### 2.3 属性词检索能力弱

例子：

- “绿色上衣”

这类查询的问题不在于时间地点，也不在于粗标签，而在于：

1. 当前系统主要依赖：
   - 粗标签
   - 通用语义
2. 但“颜色 + 穿着 + 局部属性”属于**细粒度视觉属性检索**
3. 如果当前 embedding 本身对“绿色上衣”不够敏感，就很难召回
4. 而且这种查询通常没有稳定的粗标签可以辅助

### 2.4 “旅游照片”召回严重不足

“旅游照片”按用户心智应当是一类**集合型抽象主题**，通常应覆盖：

- 人物合影
- 花草
- 地标
- 建筑
- 街景
- 美食
- 海边
- 交通

但当前很容易漏掉其中很多图片。

根因大概率是：

1. `DeepSeek 解析出的 coarse_tags 太窄`
   - 例如只返回 `travel_landmark`
   - 但没有扩展到 `city_street / natural_landscape / people / food_drink / beach_water`

2. `positive_semantics 太单一`
   - 例如只生成“landmark travel photo”
   - 却没有生成“travel portrait”, “travel dining”, “travel street scene”, “vacation memory”

3. `粗标签过滤是硬过滤`
   - 一旦粗标签集合窄，漏召回会非常严重

### 2.5 只放宽时间/地点还不够

当前“召回失败 -> 放宽时间/地点”这一步是合理的，但不够。

对于很多查询，真正限制召回的不是时间地点，而是：

- 粗标签过窄
- 正向语义太具体

因此在“结果为空”或“结果过少”时，后续还应支持：

1. 放宽标签限制
2. 取消标签限制
3. 扩展正向语义
4. 降低严格命中阈值，转入“相关结果”模式

---

## 3. 对当前实现的判断

### 3.1 当前公式的问题

当前思路里，时间、地点、标签本质上都属于**筛选条件**，不是排序特征。

因此最终得分不应该再混入：

- 时间加分
- 地点加分
- 标签加分

正确理解应当是：

1. 时间、地点先过滤
2. 粗标签再过滤或限缩候选集
3. 只在候选集内计算：

```text
final_score = positive_score - alpha * negative_score
```

其中：

- `positive_score`：正向语义加权得分
- `negative_score`：负向语义加权惩罚

这一点已经是下一步实现的基本方向。

### 3.2 当前最缺的是“召回扩展层”

现在系统已经有：

- 解析
- 过滤
- 向量打分

但缺少一层关键能力：

**用户查询 -> 多视角召回展开**

也就是把一句自然语言，扩展成：

- 核心语义
- 近义表达
- 场景化表达
- 抽象情绪映射
- 属性表达
- 主题集合展开

这层如果不补，排序再怎么调，也只能在一个很窄的候选集里排。

---

## 4. 修改思路

### 4.1 新增“查询类型识别”

在进入检索前，先识别查询属于哪一类：

1. 元数据型
   - 例：`2026年的图片`、`上海的图片`
   - 不需要语义，不需要标签

2. 明确视觉属性型
   - 例：`绿色上衣`、`红色裙子`
   - 重点是颜色、服饰、局部视觉属性

3. 具体主体/场景型
   - 例：`笑脸`、`花`、`猫`

4. 抽象氛围/情绪型
   - 例：`春天的气息`、`快乐的时光`

5. 集合主题型
   - 例：`旅游照片`、`校园生活`

不同类型，应该走不同的召回策略。

### 4.2 新增“召回扩展层”

建议在解析结果中新增一个概念：

- `recall_semantics`

它和 `positive_semantics` 的区别：

1. `positive_semantics`
   - 用于最终精排
   - 更准确、更收敛

2. `recall_semantics`
   - 用于扩大候选召回
   - 更宽、更覆盖用户可能接受的结果

例如：

#### 查询：“笑脸”

可扩展为：

- `a smiling face`
- `a happy person smiling`
- `a cheerful group photo`
- `a person smiling among flowers`
- `a happy travel portrait`

#### 查询：“春天的气息”

可扩展为：

- `a photo of spring flowers and fresh plants`
- `a person taking photos among flowers in spring`
- `a park scene in spring`
- `a bright outdoor spring day`
- `a soft fresh spring atmosphere`

#### 查询：“快乐的时光”

可扩展为：

- `a happy smiling moment`
- `a joyful travel memory`
- `a cheerful family gathering`
- `a happy dining moment`
- `a celebration full of joy`

#### 查询：“旅游照片”

可扩展为：

- `a travel memory photo`
- `a sightseeing landmark photo`
- `a travel portrait`
- `a street scene during travel`
- `a travel food photo`
- `a beach vacation photo`

### 4.3 加强 DeepSeek 的解析职责

DeepSeek 未来输出不应只有：

- 时间
- 地点
- coarse_tags
- positive_semantics
- negative_semantics

还应增加：

1. `query_type`
   - metadata
   - attribute
   - concrete
   - abstract
   - collection

2. `recall_semantics`
   - 用于宽召回

3. `estimated_result_count`
   - 预计这类查询大约应该召回多少张图片
   - 例如：
     - `绿色上衣` 可能很少，`1-10`
     - `婚礼` 可能少，`1-20`
     - `快乐的时光` 可能很多，`20-200`
     - `旅游照片` 很可能很多，`30-300`

4. `tag_strictness`
   - strict / prefer / optional

这样后续检索策略才能按查询类型自动调节。

### 4.4 调整粗标签的角色

粗标签不应永远是“硬过滤”。

建议改成三档：

1. `strict`
   - 明确指向性很强时使用
   - 例：`代码截图`

2. `prefer`
   - 默认模式
   - 先用粗标签缩小候选，但当结果过少时允许取消

3. `optional`
   - 抽象查询使用
   - 只作为辅助，不阻塞召回

#### 关键结论

对于：

- `旅游照片`
- `快乐的时光`
- `春天的气息`

这类抽象/集合型查询，粗标签绝不能是强限制。

### 4.5 增加“少结果 / 空结果”的多级放宽策略

现在只放宽时间地点，不够。

应改成多级召回策略：

#### Level 0

- 原始时间/地点
- 原始粗标签
- 原始正向语义

#### Level 1

- 放宽时间/地点
- 保留粗标签
- 保留原始正向语义

#### Level 2

- 放宽时间/地点
- 将粗标签从 strict 降到 prefer，或直接取消
- 加入 `recall_semantics`

#### Level 3

- 取消粗标签限制
- 使用更宽的 `recall_semantics`
- 降低“相关结果”的进入阈值

触发条件建议结合：

- `结果为空`
- `结果数量 < estimated_result_count * 某个比例`
- 或 `结果数量 < 最低门槛`

例如：

- `estimated_result_count <= 5` 时
  - 搜到 1 张也可能合理
- `estimated_result_count >= 50` 时
  - 只搜到 2 张就应该自动进入放宽逻辑

### 4.6 加强属性词检索

对于：

- 绿色上衣
- 红色裙子
- 白色帽子

这类查询，当前纯靠通用语义 embedding 容易不稳定。

建议新增“属性语义模板扩展”：

例如“绿色上衣”自动展开为：

- `a person wearing a green top`
- `a person in green clothes`
- `a portrait with a green shirt`
- `upper body clothing in green`

并可在未来考虑补一层“属性词典”：

- 颜色
- 服饰
- 姿态
- 人物数量

这类查询一般不应绑定粗标签。

### 4.7 加强抽象词的场景映射

需要建立一层“抽象词 -> 具象场景集合”的映射。

#### 例：春天的气息

映射到：

- 花
- 草地
- 公园
- 蓝天
- 户外人像
- 明亮色调

#### 例：快乐的时光

映射到：

- 笑脸
- 聚餐
- 旅游
- 节庆
- 合影
- 生日

#### 例：温柔

映射到：

- 柔和人像
- 花
- 日落
- 室内安静时光

这一层可以先做规则版，后续再交给 LLM 自动生成。

## 5. 对五个具体问题的修改建议

### 5.1 “笑脸”搜不到

建议：

1. 为“笑脸 / 微笑 / 开心”加入抽象场景扩展
2. 不要只生成“笑脸特写”语义
3. 在这类查询上把粗标签降为 `prefer`
4. 允许：
   - 人物合影
   - 旅游中的笑容
   - 花中人像
   - 聚餐中的笑容

### 5.2 抽象语义能力不足

建议：

1. 新增 `query_type = abstract`
2. 抽象词默认生成：
   - 核心语义
   - 场景化语义
   - 氛围语义
3. 抽象词查询下，粗标签不设为强限制

### 5.3 “绿色上衣”效果差

建议：

1. 识别为 `attribute` 查询
2. 不依赖粗标签
3. 生成多组属性模板语义
4. 后续考虑为颜色/服饰增加专门词典

### 5.4 “旅游照片”严重漏召回

建议：

1. DeepSeek 输出的 coarse_tags 必须明显更宽
2. 正向语义至少覆盖：
   - travel portrait
   - landmark travel photo
   - city street during travel
   - travel food
   - vacation by the sea
   - scenic nature during travel
3. 粗标签只做 `prefer`，结果少时自动取消

### 5.5 空结果/少结果时不仅放宽时间地点，也放宽标签

建议：

引入：

- `estimated_result_count`
- `tag_strictness`
- `recall_semantics`

并按结果数量自动升级放宽等级。

---

## 6. 推荐实施顺序

### Phase 1：先救召回

1. 扩展 DeepSeek 输出结构：
   - `query_type`
   - `recall_semantics`
   - `estimated_result_count`
   - `tag_strictness`
2. 修改搜索服务：
   - 少结果时放宽标签
   - 不只放宽时间地点

### Phase 2：补抽象语义与属性词

1. 加入抽象词场景映射
2. 加入颜色/服饰属性模板

### Phase 3：细调阈值与策略

1. 针对抽象查询单独调阈值
2. 针对属性查询单独调阈值
3. 区分精确结果与相关结果的触发条件

---

## 7. 关键结论

这次问题的核心不是“向量不够强”，而是：

1. 查询解析太窄
2. 粗标签限制过早、过硬
3. 抽象语义没有展开
4. 少结果时放宽策略不够完整

下一步真正应该做的，不是单纯继续调一个阈值，而是补齐这三层能力：

1. **查询类型识别**
2. **召回语义扩展**
3. **多级放宽策略**

这样才能系统性解决：

- 笑脸
- 春天的气息
- 快乐的时光
- 绿色上衣
- 旅游照片

这些当前最影响体验的召回问题。
