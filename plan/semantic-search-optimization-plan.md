# 语义搜索优化方案 v3

## 1. 目标

本文档用于整理当前“相册 -> 顶部语义搜索”的下一阶段优化方案，重点覆盖以下问题：

1. 不能只命中标签就展示，必须有语义权重参与。
2. DeepSeek 需要输出各个正向语义权重，最终分数不能再只取 `max`。
3. 对简单人物词或简单短语，不必调用 DeepSeek，但也不能退化成纯标签检索。
4. 未命中时要明显提示“未找到您所需的图片，只找到一些相关图片”。
5. 搜索结果页右下角要支持“生成故事”，并接入现有故事生成链路。
6. 搜索结果页要支持多种排序、地点分类、标签分类、二次搜索。

## 2. 当前实现的问题判断

### 2.1 当前主链路

当前语义搜索主链路大致是：

1. 解析自然语言，得到时间、地点、粗标签、正向语义、负向语义。
2. 先按时间/地点做硬过滤。
3. 再按粗标签收缩候选集。
4. 再用正向语义、负向语义、标签 bonus、地点 bonus、文本 bonus 做排序。
5. 无结果时回退到标签/OCR/文本线索排序。

对应文件：

- `lib/service/semantic_query_parser_service.dart`
- `lib/service/semantic_photo_search_service.dart`
- `lib/view/pages/album_search_page.dart`

### 2.2 关键问题

当前仍有几个结构性问题：

- 仍可能出现“语义不够强，但凭标签、地点、文本 bonus 也被展示”的情况。
- 正向语义分数仍偏向单一命中，缺少多语义加权。
- 简单查询目前的路由逻辑还不够准确。
- “精确命中”和“相关结果”没有清晰分层。
- 搜索结果页还没有接入故事生成和完整的多维浏览能力。

## 3. 核心原则

### 3.1 主结果必须由语义驱动

后续主结果必须满足：

- 有正向语义分数参与
- 正向语义达到门槛

不能再出现：

- 只命中标签就进入主结果
- 只命中地点/时间就进入主结果
- 只靠 OCR/caption 线索就进入主结果

这些信号最多只能作为：

- 相关结果的依据
- 或主结果中的辅助加分项

### 3.2 短查询不等于标签检索

这是本轮文档修正的重点。

对于非常短的查询，如果不需要调用 LLM，**正确做法不是“直接查标签”**，而是：

- 把用户输入视为一个极短语义查询
- 转成向量友好的英文图片描述
- 直接与图片向量做语义匹配

也就是说：

- 不调用 DeepSeek
- 但仍然做语义检索
- 标签只作为辅助信号，不是唯一判据

## 4. 查询路由设计

### 4.1 先判断是否需要 LLM

这一段采用你的思路，修正为以下规则。

后续查询入口不应简单分成“短词 = 标签检索，长句 = LLM”，而应先判断：

#### Route A：短查询直做语义检索，不走 LLM

满足以下条件时，不调用 DeepSeek：

1. 查询长度为 `1-3` 个中文字符。
2. 用户输入与某一粗标签的语义相似度达到某一阈值。
3. 查询中不包含明显的时间、地点、排除条件。

这里最重要的一点是：

- **不需要 LLM，不代表只做标签检索**

而应当：

1. 把用户输入转成适合图文向量模型的英文表达。
2. 用该表达生成文本向量。
3. 直接与图片向量做相似度匹配。
4. 标签命中只作为辅助加分或辅助过滤信号。

典型例子：

- `人物`
- `自拍`
- `宠物`
- `家人`
- `海边`
- `夜景`

这类查询都可能与某个粗标签高度相关，但不应只停留在“命中标签”，而应继续走一层短语语义检索。

#### Route B：结构化复杂查询，走 DeepSeek

以下情况必须走 DeepSeek：

- 含时间条件
- 含地点条件
- 含排除条件
- 含明显多意图组合
- 含“人物 + 场景 + 行为 + 节日/事件”复合描述

典型例子：

- 春节团聚吃饺子的图片
- 去年上海旅游照片，不要截图
- 在青岛海边和家人的合照
- 只要婚礼现场，不要自拍和文档

### 4.2 短查询直搜的语义判定逻辑

建议后续实现如下：

1. 先判断查询是否为 `1-3` 个中文字符。
2. 用该查询与所有粗标签语义原型做一次相似度比较。
3. 如果与某一个粗标签语义原型的相似度达到阈值，则判定为“短查询直搜”。

这里的判定依据不是：

- 是否刚好等于某个标签名

而是：

- 是否在语义上足够接近某个粗标签原型

### 4.3 短查询的英文改写原则

短查询不走 LLM 时，仍然要把中文输入转成适合向量检索的英文 prompt。

建议采用本地模板化改写，而不是调用大模型翻译。

原则如下：

1. 改写结果必须是图片友好的英文短句。
2. 格式尽量稳定，避免裸词。
3. 优先使用以下模板：

- `a photo of ...`
- `people ...`
- `a scene of ...`
- `an image of ...`

示例：

- `人物` -> `a photo of people`
- `自拍` -> `a selfie photo`
- `家人` -> `a photo of family members`
- `宠物` -> `a photo of a pet`
- `海边` -> `a photo at the beach`
- `夜景` -> `a city night scene`

关键目标不是“翻译得文学化”，而是“翻译得适合 CLIP / MobileCLIP 这类图文模型理解”。

### 4.4 简单查询不是纯标签检索

这一点需要明确写死，防止后续实现走偏。

短查询如果不需要 DeepSeek，正确链路应为：

1. 本地识别是否属于短查询直搜。
2. 构造向量友好的英文语义短句。
3. 生成文本向量。
4. 与图片向量做直接语义匹配。
5. 标签命中仅作为辅助排序或辅助解释。

不是：

1. 找到对应标签。
2. 只按标签返回图片。

## 5. DeepSeek 输出结构升级

### 5.1 结构化输出

建议 DeepSeek 输出结构升级为：

```json
{
  "time_ranges": [],
  "locations": [],
  "coarse_tags": [],
  "positive_semantics": [
    {
      "text": "a family reunion during Chinese New Year",
      "weight": 0.42
    },
    {
      "text": "people eating dumplings together",
      "weight": 0.33
    },
    {
      "text": "a festive Spring Festival dinner",
      "weight": 0.25
    }
  ],
  "negative_semantics": [
    {
      "text": "a screenshot of a mobile phone",
      "weight": 0.40
    },
    {
      "text": "a photographed document",
      "weight": 0.35
    },
    {
      "text": "a blurry image",
      "weight": 0.25
    }
  ],
  "notes": "..."
}
```

要求：

- `positive_semantics.weight` 建议归一化到 `1.0`
- `negative_semantics.weight` 也建议归一化到 `1.0`
- 越核心的语义，权重越高

### 5.2 正向语义分数：从 `max` 改为加权求和

后续正向语义不再取最大值，而改为：

```text
对每个正向语义 i：
sim_i = cosine(image, semantic_i)

如果 sim_i < 正向参与阈值，则该语义记为 0，不参与最终加权

S_pos = sum(weight_i * sim_i) / sum(active_weight_i)
```

其中：

- `active_weight_i` 指真正达到参与阈值的语义项权重
- 如果所有正向语义都没有过阈值，则这张图不能进入“精确命中结果”

### 5.3 正向语义门槛

建议引入两个阈值：

#### 阈值 A：语义参与阈值

建议初始值：

```text
0.20
```

作用：

- 低于 `0.20` 的正向语义匹配一律按 `0` 处理

#### 阈值 B：精确命中阈值

建议初始值：

```text
0.24
```

作用：

- 当 `S_pos >= 0.24`，才允许进入“精确命中结果”
- 当 `0 < S_pos < 0.24`，最多进入“相关结果”

### 5.4 负向语义分数

建议负向语义采用加权惩罚：

```text
S_neg = sum(weight_j * sim_j)
```

最终分数：

```text
S_final = S_pos - alpha * S_neg + tag_bonus + metadata_bonus + lexical_bonus
```

建议初始值：

```text
alpha = 0.6
```

## 6. 主结果与相关结果分层

### 6.1 精确命中结果

必须满足：

- 正向语义达到精确命中门槛
- 标签、地点、时间等只作为辅助信号

### 6.2 相关结果

如果以下信号命中，但正向语义不足：

- 标签
- 时间
- 地点
- OCR
- caption

则进入“相关结果”，而不是主结果。

### 6.3 未命中提示

当没有精确命中、只有相关结果时，页面顶部必须显著提示：

```text
未找到您所需的图片，只找到一些相关图片
```

并补一句说明，例如：

```text
这些图片与您的时间、地点、标签或部分语义相关，但未达到精确语义命中标准。
```

## 7. 搜索结果页功能增强

### 7.1 多维浏览

搜索结果页建议支持：

1. 按最终分数排序
2. 按时间降序
3. 按时间升序
4. 按地点分类
5. 按标签分类
6. 标签二级筛选
7. 结果内二次搜索

### 7.2 二次搜索

结果内二次搜索的含义是：

- 基于当前结果集继续缩小范围

例如：

- 第一次：`春节团聚吃饺子的图片`
- 第二次：在结果内再搜 `北京`

结果内二次搜索建议优先做局部过滤，不重新跑全量 DeepSeek。

## 8. 搜索结果页接入“生成故事”

### 8.1 目标

在搜索结果页右下角增加与标签预览界面一致的“生成故事”能力。

### 8.2 参考现有链路

现有故事生成链路已经存在于：

- `lib/view/pages/create_page.dart`
- `lib/view/pages/config_page.dart`

其本质流程是：

1. 用户勾选多张图片
2. 点“生成故事”
3. 组装虚拟 `Event` + `AITheme`
4. 跳转 `ConfigPage`

### 8.3 搜索结果页接入方式

建议新增：

- 右下角悬浮按钮 `生成故事`
- 多选模式
- 全选 / 清空 / 取消
- 当前可见结果集选图
- 复用已有 `ConfigPage` 跳转链路

## 9. 推荐的数据结构升级

### 9.1 查询模型

建议升级为：

```text
SemanticSearchQuery
- rawQuery

- negativeSemanticsWithWeight
```

```text
SemanticSearchResult
```

## 10. 分阶段实施建议

### Phase 1：先把算法收紧

优先做：

1. 不允许标签单独成为主结果
2. DeepSeek 输出正向语义权重
3. 正向分数从 `max` 改成加权求和
4. 简单短查询改为“短语语义直搜”，而不是“纯标签直搜”

### Phase 2：明确分层展示

1. 区分精确结果与相关结果
2. 顶部显著提示“未找到您所需的图片，只找到一些相关图片”
3. 每张结果卡片解释其命中原因

### Phase 3：增强浏览能力

1. 时间排序
2. 地点分类
3. 标签分类与二级筛选
4. 结果内二次搜索

### Phase 4：接故事生成

1. 搜索结果页增加多选模式
2. 接右下角“生成故事”
3. 复用现有 `ConfigPage` 生成链路

## 11. 最终结论

如果把本轮修正后的思路浓缩成一句话，可以表达为：

“后续语义搜索要从‘标签辅助的宽召回排序’升级为‘查询分流 + 短查询语义直搜 + 结构化 LLM 检索 + 带权语义打分 + 精确/相关双层结果 + 多维浏览 + 故事生成接入’的完整工作流。”

这次修正最关键的一点是：

- **短查询如果不走 DeepSeek，也仍然应该走语义向量检索，而不是简单退化成标签检索**

这条原则应作为后续实现时的硬约束。
